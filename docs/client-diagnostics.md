# 托管客户端诊断日志

从应用启动开始记录结构化时间线，包含登录、配置刷新、选线、分流应用、连接状态、
前后台切换、请求结束原因、耗时和收发字节数。文件位于应用数据目录的 `diagnostics/`，
四个轮转文件合计最多 20 MiB，满后覆盖最旧记录；不是无限保留本次启动以来的全部历史。
界面进程被系统终止后，不声称继续记录该进程的行为。内存队列最多 512 条，重复轮询和
队列溢出按计数记录，存储故障会阻止导出，不能伪装成完整报告。

## 隐私边界

- 写入前使用字段、类型和枚举白名单，不保存任意原始日志文本
- 不记录订阅链接、服务器域名/IP/端口、密码、会话令牌、原始配置、请求头或输入内容
- 请求只保留传输类型、直连/代理/拒绝、结束原因、耗时和字节数，不保留目标地址或节点链
- 已有原始消息仅在内存中分类为固定事件和错误类型，不通过字符串替换后直接落盘
- 导出再次校验全部记录；后台在每个分块落盘前按相同规则校验
- 签发密钥只在后台；现有登录会话换取短期投递凭证，日志直接上传 pan，不经 FC
- 投递凭证不能登录网盘、读取、列目录或覆盖他人的文件

这是保留排障行为和指标的诊断日志，不是完整配置转储或网络抓包。新增字段必须先判断
是否可能携带连接参数，再同步客户端、后台白名单及敏感值负例测试。

## 分享与保存

“我的 → 诊断 → 上传诊断日志”生成 pan 日志文件链接并尝试复制。只有网盘管理员能读取，
拿到链接本身不会获得权限。复制失败时仍显示可选择的链接，重试复制不重新上传。
上传失败不删除本地日志；可使用相邻的“保存日志文件”入口。

上传仅由用户点击触发，不自动上传或远程开启日志。单次快照最多 20 MiB，按完整行分成
不超过 256 KiB 的分块；序号、整包 SHA-256 和幂等重试防止重复追加或上传错包。
服务端校验完成后立即归档，不转存第三方平台、不使用异步发布任务。取消会清理尚未完成的
分块；已经归档的报告不会因关闭页面而撤回。每个账号最多发起 3 次/小时，报告保留
30 天，总容量最多 5 GiB。只有剩余磁盘大于 1 GiB 才接受新任务。

服务端部署、凭据轮换和恢复入口见 ops 仓 `docs/harborproxy-logdrop.md`。

## 定向验证

- `flutter test test/common/diagnostic_journal_test.dart`：保密、容量、轮转、离线程校验、分块、取消
- `bash tool/test_managed.sh`：诊断菜单、上传/复制失败、离开页面及桌面/手机布局
- `CGO_ENABLED=0 go test . -run TestClientDiagnosticUpload`（`core/`）：会话传递及错误信息边界
- 原生验收检查实际日志文件、上传链接、剪贴板和文件保存，不以 widget 测试冒充系统能力
